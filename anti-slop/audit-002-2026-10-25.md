# OpenPark app audit 002

Date: 2026-10-25
Scope: `apps/web` resident surface after the "Parking Passes" navigation change: `src/menu.ts`, `src/components/AppMenu.tsx`, `src/screens/Resident.tsx`, the resident strings in `src/locales/*.json`, and the resident styles in `src/styles.css`. The API and marketing surfaces were not re-audited; audit 001 covered the broader web surface.

Design read: operations PWA for residents, staff, and administrators, using OpenPark's existing neutral and green visual language. Dials: ENERGY 1 / RHYTHM 1 / MOTION 1. The resident screen is a single operational screen: the sidebar is wayfinding, the active pass is the primary state, and the profile pencil is a secondary action. The new menu destination is correct; the findings below are about the screen it opens.

## Findings

1. **HIGH, R-02, terminology drift:** The menu says "Parking Passes" (`apps/web/src/locales/en.json:239`), but the no-name page title is "Guest parking" (`:248`) and the admin no-unit message says "To use the resident view..." (`:595`). Every locale carries the old wording. Reason: the destination and its screen use different names, so the rename is incomplete. Fix: use "Parking Passes" for the destination and keep "guest pass" for the object; update `res.title` and `res.noUnitAdmin` in every locale, including the generated pseudo-locale.

2. **HIGH, R-02, R-05, C-3, the active pass is hidden behind a collapsed "New guest parking pass" disclosure:** `newOpen` starts false unless the URL carries `#new` (`apps/web/src/screens/Resident.tsx:102-104`). The resident login redirect lands on `/t/:slug/r` without a hash (`apps/web/src/app-context.tsx:59-63`), so the active pass, QR, countdown, and cancel/regenerate actions are not rendered. The existing test codifies the collapsed default (`apps/web/test/resident-view.test.tsx:122`). When the section is open with an active pass, its title still says "New guest parking pass" (`res.sectionNew`). Reason: the screen's primary state is hidden on first load and misnamed when shown. Fix: render the active pass outside the disclosure, or default the section open when a pass exists and title it by state ("Your guest pass" vs "New guest parking pass").

3. **HIGH, R-27, request errors and loading states are hidden inside collapsed sections:** `active.error`/`active.loading` are inside the first `Collapsible` (`apps/web/src/screens/Resident.tsx:195-197`), and `history.error`/`history.loading` are inside the second (`:253-254`). On a plain `/r` visit both sections are closed, so a failed active-pass request looks like an empty screen. Reason: a required error state is unreachable until the resident opens a disclosure. Fix: surface request errors above the disclosures, or force the affected section open on error.

4. **HIGH, R-02, R-17, the notification help describes the fine policy and hardcodes 12 hours:** The checkbox says "Notify me when my guests check in and out" (`apps/web/src/screens/Resident.tsx:369`), but `res.notifyHelp` (`:370`) says "If a guest stays longer than 12 hours, a fine is charged..." The toggle controls check-in/out messages, which `res.phoneHelp` already explains; `maxStayHours` is configurable from 1 to 72 (`apps/api/src/services/passes.ts:21`), and the pass form uses `{hours}` (`Resident.tsx:216`). Reason: the help text describes a different setting and a number that can be wrong. Fix: replace it with copy about the notification toggle, or remove it; let the pass form state the policy with `{hours}`.

5. **HIGH, R-36, an unknown issuer is labeled "host":** `res.issuedBy_unknown` is "Issued by host" in every locale, and the history falls back to it when `issuedByRole` is missing (`apps/web/src/screens/Resident.tsx:261`). The API returns `'unknown'` when `created_by` is null (`apps/api/src/services/passes.ts:112`). The test comment calls the legacy case "labelled neutrally" (`apps/web/test/resident-view.test.tsx:161`), but the copy is not neutral. Reason: the UI asserts an issuer the data does not have. Fix: "Issuer unknown" or omit the issuer line when unknown.

6. **HIGH, R-32, closing the profile editor drops focus and the expanded state has no controlled target:** The pencil button sets `aria-expanded={editing}` (`apps/web/src/screens/Resident.tsx:186`) but has no `aria-controls`, and the editor has no id. Cancel and Save call `onDone` (`:191`, `:372`), which unmounts the editor and leaves focus on the body. Reason: keyboard and screen-reader users lose the relationship and their place, and the pencil is now the only profile entry point. Fix: give the editor an id and `aria-controls` (or always render it hidden), and return focus to `profileHeadRef` when it closes.

7. **HIGH, R-03, the unit pill is off-center in RTL:** `.avatar-pill` uses `inset-inline-start: 50%` with a physical `translateX(-50%)` (`apps/web/src/styles.css:226`). In RTL, `inset-inline-start` resolves to `right`, so the negative translate shifts the pill left of center. The app sets `dir` from the locale (`apps/web/src/i18n.tsx:78`) and ships Arabic. Browser measurement: LTR offset 0 px; RTL offset -44.63 px, half the pill's width. Reason: the centering transform is not direction-aware. Fix: add `[dir='rtl'] .avatar-pill { transform: translateX(50%); }` or use a direction-neutral centering technique.

8. **LOW, R-31, the new menu label is title case in a sentence-case menu:** `nav.parkingPasses` is "Parking Passes" (`apps/web/src/locales/en.json:239`), while the other nav labels are sentence case ("Platform view", "Operator view", "Rate plans", "Guest passes"). Reason: an unexplained style break. Fix: "Parking passes", or record why this one is a product name.

9. **LOW, R-31, stale comments still describe a sidebar `?edit=1` link:** `apps/web/test/resident-view.test.tsx:64-65` says the deep links mirror "how the deep-links in the sidebar deliver them"; the sidebar now delivers only `#new`. `apps/web/src/screens/Resident.tsx:52-53` says the disclosure is driven by "#new / ?edit=1", but `?edit=1` opens the profile editor, not the disclosure. Reason: comments describe a navigation that was removed. Fix: update both comments to describe direct/bookmarked deep links and the actual target.

## Verification evidence

- Source inspection of the files above, including every locale file.
- Focused tests: `pnpm --filter @openpark/web exec vitest run test/resident-view.test.tsx test/menu.test.ts test/shell-collapse.test.tsx` passed, 3 files and 37 tests.
- Contrast check for the resident badge, banner, avatar, and muted-text combinations passed WCAG AA in both themes: light 4.64:1 to 7.24:1, dark 6.45:1 to 8.53:1.
- RTL measurement in Playwright with installed Chrome: `.avatar-pill` center offset 0 px in LTR and -44.63 px in RTL.
- Not run: a full browser walkthrough of the resident screen with live API data. Findings 2 through 6 are from source inspection and the existing tests.

No files were changed at audit time. All 9 findings were approved and fixed on 2026-10-25; see `audit-002-2026-10-25-fixes.md` for the fix record and verification evidence.
