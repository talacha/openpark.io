# Implementation Plan — OpenPark adversarial review-and-implement loop

Scope: harden an already-built pnpm monorepo against 7 acceptance criteria plus the cross-cutting
bars (UX, a11y, mobile-first/responsive, performance, security). The app is substantially built; most
criteria need verification and polish, and two need REAL code changes:
(a) the resident SHARE affordance for the QR pass (criterion 1), and
(b) the currency-keyed overstay DEFAULT/SEED + "move the vehicle" messaging (criterion 5).

Planning mode: no approved design doc was supplied, so design decisions here are mine, grounded in the
code I read; each is recorded inline in one or two sentences. Where approaches were viable I picked one
and said why.

Workflow decomposition decision: NOT restructured into FEATs. The existing implement-and-review loop
already encodes the exact contract this run requires — up to 10 fix/review iterations OR reviewer reports
no blocking/high/medium findings OR 12h wall-clock from `.agents/reviews/run-start.txt`
(2026-10-21T03:52:23Z); reviewer writes `.agents/tasks/review-verdict.json` with `verdict` = `APPROVED`
to stop; per-tick publish (commit on `adversarial-loop`, fast-forward and push `main` only when the gate
is green); running `.agents/reviews/LOOP-SUMMARY.md` trail; implementation on wf-coder and adversarial
review on wf-code-reviewer with a different model. A FEAT convergence-loop tail (≤2 iterations, different
verdict path, no per-tick publish, no 12h budget) would break that contract, so the single ordered plan
below is the right artifact for the loop to consume.

## Verification gate (every item below must leave this green before it reports success)

```
pnpm --filter @openpark/core build   # REQUIRED first: api/web import core's dist/
pnpm typecheck                        # 7 projects
pnpm test                             # core 36, sdk-ts 6, marketing 9, web 52, api 99 (api needs Postgres at :54329)
pnpm --filter @openpark/web check:css # RTL guard: fails on physical left/right CSS
```
Baseline is stated green (212 tests). Never weaken, skip or delete a test to pass. New UI strings go in ALL
seven web locale files (`apps/web/src/locales/{en,es-MX,es-ES,pt-BR,fr,de,ar}.json`); `en-XA.json` is
generated by the build — do not edit it. New tenant tables need RLS + a grant to `openpark_app`; history
tables stay insert-only. Money is integer minor units. Note on method: status below was verified by reading
code and tests in this worktree, NOT by executing the gate during planning — each item's Verify line is the
command the implementer must actually run.

- [ ] 1. Criterion 5 (part A) — seed the overstay default off the tenant CURRENCY, not the country.
      Current status: VERIFIED in `apps/api/src/services/tenants.ts` `provisionTenant()` the seed is
      `overstayCharge: input.country === 'MX' ? 500000 : 0`. That is keyed off the country code, but the
      criterion requires it keyed off the tenant currency (MXN). `DEFAULT_POLICY` in
      `apps/api/src/services/passes.ts` keeps the field (default 0) and PATCH `/v1/pass-policy` keeps it
      editable — leave both as-is. Decision: change the seed to key off the resolved currency
      (`c.currency === 'MXN' ? 500000 : 0`, where `c = COUNTRIES[country] ?? DEFAULT_COUNTRY`); do not
      hardcode 500000 globally or for non-MXN tenants. Behaviour is unchanged for today's country set
      (MX→MXN→500000, US→USD→0) so existing assertions still hold, but intent now matches the requirement.
      This is a configurable policy only — build NO enforcement, billing or payment collection.
      Files: `apps/api/src/services/tenants.ts`.
      Verify: `pnpm --filter @openpark/core build && pnpm --filter @openpark/api test` — `identity.test.ts`
      (MX default 500000), `closed-preview.test.ts` (MX→500000, US→0) and `passes.test.ts` still pass; add a
      case asserting a USD-currency tenant seeds `overstayCharge` 0 and an MXN one seeds 500000.

- [ ] 2. Criterion 5 (part B) — put the "move the vehicle" instruction in the 12h overstay notification,
      with the amount currency-formatted from the policy value (not a literal), reminders unchanged.
      Current status: VERIFIED. `apps/api/src/services/passes.ts` `sendPassNotification()` already formats
      `{amount}` via `new Intl.NumberFormat(locale, { style: 'currency', currency }).format(charge/100)`
      from `pass.overstay_charge ?? policy.overstayCharge`, and the 10h/11h path uses the `reminder` key
      (leave it alone). Gap: the `overstay_guest` / `overstay_host` / `overstay_staff` bodies in
      `apps/api/src/notify/messages.ts` state the HOA charge but never tell the host to move the vehicle.
      Decision: append a "please move the vehicle" sentence to those three message bodies in every catalog
      (en, es-MX, es-ES, pt-BR, fr, de, ar); keep `{amount}` and — for es-MX, which `passes.test.ts:290`
      asserts — keep the literal substring `plataforma del HOA` and the `$5,000.00` amount intact. `esES`
      spreads `esMX`, so it inherits the overstay bodies unless overridden; update the base objects so all
      locales get the sentence. No new placeholder is needed (static sentence per locale).
      Files: `apps/api/src/notify/messages.ts`.
      Verify: `pnpm --filter @openpark/core build && pnpm --filter @openpark/api test` — extend
      `passes.test.ts` ("reminders and the 12-hour overstay notice") to assert each 12h message body
      contains both the formatted amount and the move-vehicle phrase, and that the 10h/11h reminder bodies
      do NOT; existing `$5,000.00` / `plataforma del HOA` assertions still pass.

- [ ] 3. Criterion 1 (part A) — add a SHARE affordance so a resident can actually send the QR pass to a guest.
      Current status: VERIFIED MISSING. `apps/web/src/screens/Resident.tsx` renders `<QrCode>`, the verify
      code, a countdown and Regenerate/Cancel, but there is no way to send the pass to the guest; a resident

      Decision: add a "Share pass" button (shown only while a pass is `active` with a live `qr`) that calls
      the Web Share API with a GIF image of the QR plus a localized message (guest name, unit, site, the
      verification code, time remaining, and "show this QR at the gate"). Feature-detect and degrade: if
      `navigator.canShare({files})` is false but `navigator.share` exists, share text only; if `share` is
      absent, copy the message to the clipboard (and offer the QR image as a download) with visible
      `aria-live` feedback. Never throw on an unsupported browser. Keep pure, testable helpers in `pass.ts`:
      `qrGifDataUrl(value)`, `dataUrlToBlob(url)`, and `passShareMessage(t, { guest, unit, site, code,
      expiresMinutes })` → `{ title, text }`. A11y: real `<button>`, label, focus stays put, feedback via
      `role="status"`.
      Files: `apps/web/src/pass.ts`, `apps/web/src/screens/Resident.tsx`,
      `apps/web/src/locales/{en,es-MX,es-ES,pt-BR,fr,de,ar}.json` (new keys `res.share`, `res.shareTitle`,
      `res.shareBody`, `res.shareCopied`, `res.shareFailed`), `apps/web/test/pass.test.ts`.
      Verify: `pnpm --filter @openpark/web test` (new `pass.test.ts` cases for `qrGifDataUrl` returning a
      `data:image/gif`, `dataUrlToBlob` size/type, and `passShareMessage` filling placeholders; the locale
      key/placeholder-parity test must stay green) + `pnpm typecheck` + `pnpm --filter @openpark/web check:css`.

      Files: `apps/web/src/screens/Attendant.tsx`; extract the QR→prefill mapping into a small pure helper in

      Verify: `pnpm --filter @openpark/web test` (add a `pass.test.ts` case: a QR with a plate hint yields

## Per-tick loop contract (for the implement-and-review steps consuming this plan)

- Pick the highest-value unchecked item (roughly items 1→13), implement it, add/extend a real test, and run
  the full gate: `pnpm --filter @openpark/core build && pnpm typecheck && pnpm test && pnpm --filter
  @openpark/web check:css`. Never weaken or delete a test to go green.
- Full autonomy: when a choice is ambiguous, take the lowest-risk, most-reversible option that satisfies the
  criteria and matches existing patterns, and record the decision + rationale in the iteration's review
  report, the commit message, and `.agents/reviews/LOOP-SUMMARY.md`. Do not pause for input.
- Only when the gate is green: commit on `adversarial-loop`, fast-forward `main` in the user's checkout at
  `/Users/robcr/Projects/openpark.io`, and `git push origin main` (normal push; never force). Never publish a
  tick whose gate is not green.
- A fresh adversarial reviewer (wf-code-reviewer, model different from the implementer) reviews the diff +
  verification evidence and writes `.agents/tasks/review-verdict.json` with `verdict` = `APPROVED` (stop) or
  `CHANGES_REQUESTED` (continue). Stop at whichever comes first: `APPROVED`/no blocking-high-medium findings,
  10 iterations, or 12h from `.agents/reviews/run-start.txt` (2026-10-21T03:52:23Z).
- Hard stops (report, do not force past): a push rejected because the remote moved; a gate that cannot be made
  green with an honest fix; or any action that would touch hosted infra, apply a migration to a hosted DB, or
  exfiltrate a secret. Local test-DB migrations are fine.
